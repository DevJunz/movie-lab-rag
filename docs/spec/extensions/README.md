# 확장 SPEC (심화 이후의 추가 기능)

MVP(F2001~F2012, NF2001~NF2007)와 심화(F2013~F2016) 밖의 기능은 여기에 SPEC을 먼저 쓰고 구현한다.

## 규칙

1. **SPEC 먼저.** `../_template.md`를 복사해 `SPEC-X<3자리>-<영문-슬러그>.md`로 만든다 (예: `SPEC-X001-multi-turn-context.md`).
2. 표 머리의 "요구사항"에는 `X001 (분류 · 확장)`과 **요청 출처**(사용자 요청 원문, 날짜)를 쓴다.
3. **필수 기능의 동작을 바꾸지 않는다.** 확장이 MVP SPEC의 동작에 영향을 주면, 영향받는 SPEC과 AC를 SPEC 본문에 적는다. 그 MVP SPEC은 같은 PR에서 고친다. 이때 명세서 원문 요구는 그대로 지켜야 한다.
4. 새 가정은 `../00-product-overview.md` §8에 `A-xx`로 추가한다.
5. `../02-traceability.md`의 "확장" 표에 행을 추가한다(요구사항 · SPEC · 모듈 · AC 수 · 상태).
6. 이후 흐름은 AGENTS.md §3과 같다 (ISSUE → 브랜치 · SPEC 커밋 → TEST → 코드 → PR → CI → 리뷰 → 머지 → ISSUE 닫기).

## 후보 목록 (아직 SPEC 아님)

구현하기로 정하면 SPEC으로 옮긴다. 정하기 전에는 코드를 쓰지 않는다.

| 후보 | 내용 | 관련 |
|---|---|---|
| 대화 맥락 반영 | 이전 질문을 참고해 "그 감독의 다른 작품은?" 같은 후속 질문 처리 (A-08 변경 필요) | F2007, F2009 |
| 작품 비교 | 두 영화를 골라 근거 기반 비교 | F2010 |
| 대표 영화 일괄 사전 수집 | 인기 영화 N편을 미리 수집 · 색인해 첫 응답 시간 단축 | NF2001 |
| 하이브리드 검색 | 키워드(BM25) + 벡터 검색 결합 | F2006, F2014 |
| 자동 품질 평가 | LLM 채점으로 F2015 비교 보조 | F2015 |
